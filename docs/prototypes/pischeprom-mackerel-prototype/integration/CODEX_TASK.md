# Интеграция лендинга «Скумбрия» в Пищепром-Сервер

## Результат

Перенести реализованную страницу из `dist/index.html`, `dist/styles.css`, `dist/app.js` в существующий Laravel + Vue 3 + Inertia проект. Сохранить адаптивный дизайн, фото, справочник, инфографику, раскрывающиеся разделы и контекстные ссылки. Каталог, URL, изображения партий, цены и наличие получать из существующего каталога магазина. Не создавать второй каталог или независимую корзину.

Текущая самостоятельная версия — рабочий визуальный прототип со ссылками на реальные товары. Она не подключена к базе магазина и не изменяет его файлы. В ней намеренно нет копий цен и статусов наличия, нет фиктивного оформления заказа; кнопки ведут в реальные карточки.

## До изменений

Прочитать AGENTS.md и существующий код маршрута `/p/{product}`, контроллер, `Products/Show.vue`, `Goods/Show.vue`, связи Product/Good, классы SEO и механизм публичных цен/наличия. Проверить состояние данных заново: идентификаторы и связи могли измениться.

Уточнить по коду, является ли «Скумбрия замороженная» подтипом «Скумбрии» и есть ли уже отношение для такой иерархии. Не присоединять и не перемещать товары между классами автоматически, не создавать новые Product/Good и не заменять текущую классификацию без необходимости.

## Реализация

1. Использовать существующую страницу `/p/124` для общего гида, если это согласуется с текущим маршрутизатором и SEO. Выделить универсальный шаблон страницы класса и компоненты `ClassHero`, `ClassGoods`, `InlineGoodLink`, `ClassGuide`, `ClassSources`; не подменять весь `Products/Show.vue` специальным случаем для скумбрии.
2. Справочную статью и товарный список получать независимо. Если иерархия классов уже есть, получить опубликованные товары связанных подтипов по ней. Если её нет, оформить явную конфигурацию источников каталога для лендинга с идентификатором 201. Не искать товары по подстроке названия. Не применять эту конфигурацию ко всем классам.
3. Для каталога использовать существующий публичный сервис/ресурс Good и фильтр публикации. Не брать случайную выдачу и не копировать логику цен из шаблона. Дедуплицировать товары по Good.id, задать стабильный порядок; обрабатывать отсутствие товаров без выдуманных позиций.
4. Выдавать Vue-компоненту минимальный DTO: `id`, `name`, `url`, `image`, `image_alt`, подтверждённые атрибуты, а также цену и наличие только через действующий механизм проекта. `url` генерировать на сервере существующим именованным маршрутом и текущим slug. Уточнить имя маршрута по коду, не угадывать его.
5. Контекстные ссылки в тексте связывать с Good.id, а не с вручную записанным slug. Сначала разрешить идентификаторы опубликованных товаров на сервере. При снятии товара с публикации показывать обычный текст либо ссылку на каталог класса; не оставлять 404. При смене slug статья должна обновляться без правки текста.
6. Кнопки товара подключить к существующей карточке и процессу заказа. Существующие контакты и регионы брать из настроек. Подключение к корзине, ценам или отправке формы не имитировать локальными сообщениями об успехе.
7. Перенести стили с префиксом или scope для страницы класса, используя переменные и принципы текущего приложения. Не допустить глобального воздействия на `body`, `h1`, `.header`, `.button` или Vuetify. Общую шапку/подвал магазина переиспользовать. Лендинг работает без новых UI-библиотек.
8. Статический `app.js` заменить Vue-логикой с `onMounted`/`onUnmounted` либо штатной навигацией проекта. Не обращаться к `window` и `document` при SSR. Сохранить открытие нужного `<details>` при переходе по сноске или якорю.
9. В серверном HTML должны находиться статья, список товаров и ссылки. Согласовать `<title>`, description, H1, canonical и robots с действующим SEO-модулем. У самостоятельного прототипа стоит `noindex, nofollow`; не переносить этот тег в индексируемую production-страницу автоматически. Установить canonical только на действительный production URL.
10. Добавить `CollectionPage` и `ItemList` из реально отображаемой выдачи; `BreadcrumbList` формировать по существующей структуре. Не копировать `Offer` с устаревшей ценой, не добавлять оценки/отзывы. В sitemap оставить один действительный URL страницы класса согласно правилам проекта.

## Проверка перед включением

- `/p/124` возвращает 200 и правильный H1, canonical, статью и товары в исходном HTML.
- Все ожидаемые опубликованные Good из источников представлены один раз; нет черновиков.
- SKU 75 разрешается на текущий slug. Смена slug автоматически отражается и в каталоге, и в ссылках статьи.
- Снятый с публикации SKU не оставляет битую ссылку в статье и не появляется в каталоге.
- Контроль цены, единицы, упаковки и наличия совпадает с карточкой Good; неизвестные значения имеют честное пустое состояние.
- Переходы, якоря и раскрытие источников работают с клавиатурой. На 360, 768 и 1440 px нет горизонтального переполнения. Текст остаётся читаемым при увеличении.
- SSR не вызывает ошибок `window`, `document` или Ziggy; существующие страницы других классов не меняют поведение.
- В сети нет ненужных сторонних шрифтов/трекеров; изображения загружаются с инфраструктуры проекта. Атрибуция фотографий сохранена.

Не разворачивать изменения на основном магазине и не менять данные каталога как побочный эффект работы над прототипом. Выполнить перенос в рабочей ветке по правилам репозитория и представить конкретный diff с результатами проверок.

# Исправления почты, прайсов и доступа Ameise — 27 сентября 2026

Исходные доказательства и границы аудита: [mail-audit-2026-09-27.md](mail-audit-2026-09-27.md).

## Причины и исправления

1. Уведомления прайсов выбирали пользователей **без** разрешения: второй аргумент Spatie `User::permission($permission, 'crm')` означает `$without`, а не guard. Вызов исправлен. Получатели дополнительно проверяются на активность, подтверждённый адрес, принадлежность к сотрудникам и актуальное разрешение. Все исходящие уведомления этого модуля отключены независимо от исправления выборки.
2. В модуле прайсов отключены email, MAX, AI-классификация, AI-извлечение, AI-переранжирование и платный OCR. Проверки стоят до постановки задания, при обработке и перед внешним запросом, включая повтор HTTP-запроса. Сериализованные уведомления старого формата не отправляются. Обычный локальный разбор таблиц и текстовых документов сохранён.
3. Повторные задания извлечения/нормализации/OCR не сбрасывают подтверждённые или уже применённые строки. Перед применением цен заново проверяются сотрудник и его актуальные права. Смешанный PDF с текстовыми и сканированными страницами допускает локальное извлечение доступного текста, с предупреждением о неполноте без OCR.
4. Переполненный диск вызывал ошибки записи и срывал синхронизацию почты. После увеличения VPS файловая система видит расширенный том. Удалены только старые собранные frontend-артефакты двух деплоев от августа и пересоздаваемый индекс пакетов APT: 227 730 399 байт. БД, почтовые сообщения, вложения и все данные Avito сохранены. Таблица истории вызовов Avito занимает около 23 GiB и остаётся источником дальнейшего роста; её очистка в эту работу не входит.
5. Ручная отправка теперь до SMTP сохраняет приватный MIME-оригинал и настоящий Message-ID. После принятия SMTP отдельная операция сопоставляет копию в Sent по точному Message-ID; при отсутствии копии добавляет её через IMAP APPEND. Очередь и периодическая команда повторяют только архивирование, не отправку адресату. Ошибки IMAP и ошибки после подтверждения SMTP не показываются как «письмо не отправлено». Одновременные запросы с одним idempotency key не создают вторую отправку.
6. Исторические письма с вымышленным `@local.pischeprom` нельзя доказательно сопоставить по этому идентификатору. Для ранее пустой Sent предусмотрено восстановление из локальных данных с явной пометкой и новым Message-ID, без SMTP. Команда работает сначала в dry-run; неполные сообщения и сообщения с вложениями пропускаются. В непустую папку с неизвестными оригиналами массовое восстановление запрещено во избежание дубликатов.
7. HTML письма отображается в изолированном iframe с CSP: без выполнения скриптов, форм и загрузки внешних ресурсов. Тело письма больше не вставляется непосредственно в DOM админки.

## Общий вход

`RequireStaffAuthentication` защищает маршруты групп web/API по умолчанию, включая все Ameise и старые административные API вне этого префикса. Гость получает переход на общий `/login` для страницы или 401 для API; внешний покупатель — 403. Разрешены активные сотрудники и существующие владельцы CRM-ролей admin/manager, в том числе старый владелец с типом customer. Самостоятельная регистрация покупателя не открывает админку.

Публичные страницы магазина, личный кабинет покупателя, стандартные процедуры входа/восстановления, токенизированные ссылки и входящие callback/webhook перечислены точными URI и HTTP-методами. Мобильный API сохраняет собственные ограниченные токены. Новые маршруты автоматически требуют сотрудника. Повторяющиеся проверки входа в отдельных разделах удалены; разрешения на конкретные операции, подтверждение email и лимиты запросов сохранены.

Дополнительно обнаружен ранее незащищённый Telegram webhook, допускавший запись в Chat/Message. Для него добавлена проверка `X-Telegram-Bot-Api-Secret-Token` и ограничение частоты. Без настроенного секрета вход закрыт. Удалено логирование полного входящего события и URL файла с токеном бота. Настройка существующего webhook сохраняет URL, очередь событий и параметры; сообщения ботом не отправляются.

Обновление 2026-10-10: по решению владельца неиспользуемая интеграция Telegram удалена вместе с API-маршрутами, страницей бота, SDK и provisioning при деплое. Старый `/api/webhook` теперь отсутствует и не записывает входящие события. История `Chat`/`Message`, связи с контрагентами и защищённые API чтения сохранены. MAX, Avito и почтовые webhook продолжают использовать собственную авторизацию.

Закрыт связанный обход через публичный профиль покупателя: совпадение ИНН, email или телефона больше не даёт права изменять существующую CRM-организацию или считать себя её владельцем. Исторические связи не считаются доказательством владения. Новые организации, созданные самим покупателем, получают отдельную отметку создателя; существующие данные не переписываются. Регистрация и оформление заказа сохранены. Контакты и адрес доставки чужой организации не меняются при checkout, покупатель видит только лично созданные заказы. Удалён вложенный ORM-объект `auth.user.user`, через который могли раскрыться загруженные CRM-связи. Общие и исторические заказы остаются доступны сотрудникам в Ameise.

## Деплой и эксплуатация

Обычный GitHub Actions deploy до запуска очередей принудительно устанавливает в production:

```dotenv
AI_PRICE_LIST_NOTIFICATIONS_ENABLED=false
AI_PRICE_LIST_MAX_ACK_ENABLED=false
AI_PRICE_LIST_AI_ENABLED=false
PRICE_LIST_AI_RERANKING_ENABLED=false
AI_PRICE_LIST_AUTHORIZATION_ENABLED=true
```

Обновление `.env` атомарное, сохраняет остальные настройки и не выводит секреты. Проверка production контролирует флаги, схему и защиту маршрутов. Проверки доступности Ameise ожидают 302/401 для гостя. `mail:reconcile-sent --limit=50` запускается каждые пять минут и не использует SMTP.

После успешного GitHub Actions проверяются действующий commit на VPS, HTTP 302/401 для гостей, IMAP и SMTP AUTH обоих ящиков без отправки писем, состояние очередей и свободное место. Восстановление архивных копий выполняется только после dry-run.

Локально основной набор CI прошёл: 1495 PHP-тестов, 14122 assertions, 2 пропуска; 169 frontend-тестов; client/SSR build. Реальная проверка в локальном Chrome подтвердила блокировку script, onerror, SVG, iframe/object, внешних image/CSS-загрузок и meta-refresh в письме. Расширенный набор AI Sales выявил отдельно четыре сбоя canary-проверок с существующим фиксированным сроком доказательств 15.09.2026; они не входят в основной CI, срок не продлевался и платные canary-вызовы не включались.

## Ограничения, выявленные аудитом прайсов

Перед любым будущим включением AI потребуется отдельно доработать атомарное резервирование бюджета: текущие лимиты проверяются до запроса, оценка стоимости приблизительная, а повтор после неопределённого ответа провайдера может тарифицироваться повторно. Сейчас эти пути закрыты общим выключателем и не выполняют внешних AI/OCR-запросов.

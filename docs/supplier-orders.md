# Заказы поставщикам

В карточке Unit кнопка «Написать» открывает конструктор заказа. Обычное письмо доступно отдельным режимом; ответы на входящие письма открываются в обычном режиме. Реестр доступен в навигации Ameise → «Поставщикам», а в карточке Unit — во вкладке «Заказы поставщику».

## Работа в одном окне

Слева находятся получатели, почтовый ящик, тема, текст, срок поставки, состав заказа и предпросмотр письма. Справа — потребность клиентов, ассортимент данного поставщика и поиск по всем товарам. У строки товара можно раскрыть исходные заказы покупателей и уже оформленные заказы поставщикам. Количество добавляется вручную либо по рассчитанному дефициту; повторное добавление объединяет позицию.

Таблица письма всегда содержит закупочную цену и сумму; неизвестная цена помечается «Уточнить». Источник предлагаемой цены — предложение выбранного поставщика, пересчитанное на единицу учёта товара; цену также можно ввести вручную. Итоги считаются отдельно по валютам, а неполная оценка явно обозначается. Розничные и индивидуальные клиентские цены не используются. Внутренняя заметка, имена покупателей, их заказы и складские сведения в письмо не включаются. Предпросмотр и отправка используют один серверный HTML/text renderer; пользовательский текст экранируется.

Черновик сохраняется отдельно от отправки. Вложения выбираются в текущем окне; локальные файлы нужно прикрепить заново после закрытия черновика. Отправленное письмо и вложения попадают в существующий почтовый архив Unit.

## Потребность и единицы

Потребность — все неотгруженные, незакрытые клиентские заказы в выбранной области склада. Собранные заказы тоже учитываются: отдельного складского резервирования в проекте нет. Отложенные заказы включаются флажком. Заказы без назначенного склада входят в выбранную область. Остаток — подписанная сумма складских движений; отрицательный остаток увеличивает дефицит.

`Дефицит = max(0, потребность − остаток)`.

`К заказу = max(0, дефицит − отправленные и подтверждённые заказы поставщикам)`.

Учитываются заказы всем поставщикам, а не только открытому Unit. Черновики и отправки с неизвестным результатом показаны отдельно и не вычитаются. При ограничении потребности датой поступления после этой даты и без известной даты тоже не вычитаются. Несопоставимые единицы или масса упаковки дают предупреждение вместо предполагаемого количества. Все количества хранятся с шестью знаками, закупочные цены — с четырьмя.

Ассортимент строится по предложениям, истории закупок и импортированным прайсам связанных Entity. Связь производителя с продуктом показывается как кандидат, требующий уточнения конкретного товара.

## Хранение и жизненный цикл

`supplier_orders` хранит шапку, получателей, письмо, статус, ревизию и связь с архивным письмом. `supplier_order_items` хранит снимки названия, единицы, массы, количества, закупочной цены и внутренних связей с потребностью. Изменения каталога не переписывают отправленный документ.

Основные состояния: черновик → отправляется → отправлен → подтверждён → закрыт. Черновик, отправленный или подтверждённый заказ можно отменить; удалить можно только черновик. После отправки состав и письмо доступны для чтения. Закрытие заказа не создаёт складского прихода: фактическое поступление оформляется существующей закупкой.

Создание идемпотентно по ключу пользователя, изменения защищены номером ревизии. Отправка фиксирует ключ и блокирует документ **до** обращения к SMTP. Повторное нажатие и обращение другого сотрудника не отправляют второе письмо. Статус «Отправлен» устанавливается только по сохранённым доказательствам принятия SMTP. Неопределённый результат блокирует повтор; «Проверить статус отправки» сверяет почтовый журнал без нового SMTP. Прерванная отправка без достаточных доказательств остаётся заблокированной и требует проверки почтового журнала администратором. Подтверждённая ошибка до отправки возвращает исправляемый черновик.

Все страницы и API закрыты для посетителей и клиентов, доступны активным подтверждённым сотрудникам. Отправка дополнительно требует существующего разрешения на почту и доступа к Unit. Развёртывание через GitHub Actions применяет миграцию и проверяет закрытость новых маршрутов.

```sh
APP_URL=http://localhost php artisan test --compact tests/Feature/SupplierOrderTest.php tests/Feature/SupplierOrders tests/Unit/SupplierOrderMailRendererTest.php
node --test tests/Frontend/supplierOrder*.test.mjs
npm run build
```

Тесты отправки используют подменённый Symfony transport и изолированные хранилища; реальные письма не отправляются.

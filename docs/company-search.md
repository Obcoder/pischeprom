# Поиск компаний по ОКВЭД и возможности ФНС

Проверено 6 октября 2026 года.

## Поиск в Ameise

На странице `/Ameise/units` кнопка **«Компании по ОКВЭД»** открывает поиск через
DaData. Оператор задаёт текст поиска и основные коды ОКВЭД, просматривает результаты,
копирует ИНН и переходит к уже существующим связанным Entity/Unit.

Поиск доступен авторизованным сотрудникам и работает только на чтение: результаты
не создают Unit, Entity или связи между ними. Совпадения с локальными Entity
определяются по ИНН; вместе с ними возвращаются связанные Unit.

DaData позволяет ограничить текстовый поиск по ОКВЭД, но этот метод не предоставляет
полный список всех компаний отрасли. Он возвращает до 20 подсказок, без пагинации
и полной выгрузки. Даже если получено меньше 20 результатов, ответ не считается
исчерпывающим.

### Контракт приложения

`POST /web/units/company-search` — маршрут `web.units.company-search`.
Используется существующая сессия сотрудника и CSRF-защита web-маршрутов.
Ограничение приложения: 10 запросов в минуту.

| Поле | Правила |
| --- | --- |
| `query` | Обязательная строка от 2 до 300 символов: название, ИНН или адрес. |
| `okved` | Обязательный массив от 1 до 10 разных строк с кодами, например `10.51`, `10.51.1`. Маски не поддерживаются. |
| `status` | Необязательный массив: `ACTIVE`, `LIQUIDATING`, `LIQUIDATED`, `BANKRUPT`, `REORGANIZING`. При отсутствии используется `["ACTIVE"]`; пустой массив снимает ограничение по статусу. |
| `type` | Необязательно: `LEGAL` или `INDIVIDUAL`. Без значения поиск включает оба типа. |
| `region_code` | Необязательная строка с двузначным кодом региона, например `77` или `02`. |
| `count` | Необязательное целое от 1 до 20; по умолчанию 20. |

Пример тела запроса:

```json
{
  "query": "молоко",
  "okved": ["10.51", "10.51.1"],
  "status": ["ACTIVE"],
  "type": "LEGAL",
  "region_code": "77",
  "count": 20
}
```

Ответ содержит `data` — массив результатов с нормализованными реквизитами `entity`,
исходной подсказкой `raw` и массивом `existing_entities`. Каждый найденный локальный
контрагент содержит `id`, `name` и связанные `units` с `id` и `name`.

Метаданные пустого результата:

```json
{
  "data": [],
  "meta": {
    "source": "DaData",
    "limit": 20,
    "returned": 0,
    "exhaustive": false,
    "okved_match": "main_exact"
  }
}
```

Ошибка валидации возвращает HTTP 422, превышение частоты — HTTP 429,
некорректная структура ответа поставщика — HTTP 502. Отсутствующий токен,
ошибка доступа к DaData, сетевой сбой или недоступность поставщика возвращают
HTTP 503 с сообщением для оператора. Тело ошибки DaData и ключ не передаются клиенту.

### Особенности DaData

Сервис `DaDataCompanySearchService` вызывает
`POST https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/party`.
Поиск по ОКВЭД выполняется через `suggest/party`: метод `findById/party`, применяемый
для добавления Entity по ИНН, не подходит для этого фильтра.

Фильтр `okved` проверяет **полное совпадение основного кода**. Дополнительные коды
не учитываются; автоматического включения дочерних кодов нет. Например, `10.51`
сам по себе не включает основной код `10.51.1` — его нужно передать отдельно.
Документация разрешает максимум 10 кодов. [Фильтрация по ОКВЭД](https://confluence.hflabs.ru/pages/viewpage.action?pageId=1093075333).

`region_code` преобразуется в `locations: [{"kladr_id": "77"}]`; код региона
передаётся строкой, чтобы сохранить ведущий ноль.
[Ограничение организаций по региону](https://confluence.hflabs.ru/pages/viewpage.action?pageId=204669123).

Максимальный `count` равен 20. Непустой текстовый запрос обязателен в реализованном
интерфейсе; обходить предел результата перебором запросов сервис не пытается.
[API подсказок по организациям](https://dadata.ru/api/suggest/party/).

Используется существующая настройка `config('services.dadata.token')`, переменная
окружения `DADATA_TOKEN`. Ключ остаётся на сервере. `DADATA_SECRET`, необходимый
для других операций вроде стандартизации адресов, этому поиску не нужен.
После изменения настроек необходимо обновить конфигурационный кеш обычным
для окружения способом.

В локальном окружении при разработке `DADATA_TOKEN` отсутствовал: живой поиск
DaData не выполнялся. Проверка интеграции использует `Http::fake()` и не подтверждает
доступность конкретного аккаунта, его лимиты или реальные результаты поиска.
После настройки ключа следует выполнить один поиск из интерфейса и проверить
обработку результата и совпадения с существующими контрагентами.

## Проверенные возможности ФНС России

### Публичный API «Мой ОКВЭД»

ФНС публикует API без отдельной аутентификации. Он предоставляет справочник и
подбор кодов ОКВЭД, описания видов деятельности и связанные коды.
[Страница разработчикам](https://service.nalog.ru/okved/developers.html).

В актуальной [OpenAPI](https://service.nalog.ru/okved/api/v1/open-api.yaml) также
есть метод:

```http
GET https://service.nalog.ru/okved/api/v1/egrn/{id}
```

`id` — ИНН, ОГРН или ОГРНИП; `operationId` — `getEgrn`.
Ответ имеет форму `{"egrn": [...]}`. В спецификации элементы массива описаны
как `object`, без строгого контракта всех полей.

Выполнен один запрос по публичному ИНН юридического лица без ключа: получен
**HTTP 200**. Ответ содержит базовые реквизиты, статус, дату регистрации,
`okveds` и `reportedOkveds`; в проверенном ответе у отчётного кода есть `main`.
Адресов и контактов в проверенном ответе не было. Данные самой организации
в эту документацию не сохраняются.

Есть расхождение документов: в [PDF-описании](https://service.nalog.ru/okved/doc/open-api.pdf)
метод `/egrn/{id}` не перечислен, хотя он присутствует в действующей OpenAPI и
реально отвечает. В изученной спецификации не указаны лимиты частоты запросов
и гарантии доступности.

Метода получения списка организаций по ОКВЭД в этой OpenAPI нет. API подходит
для получения кодов и базовых реквизитов конкретного лица по идентификатору.
В текущей задаче подключение ФНС не реализовано: проверены возможность и контракт.

### Полные сведения ЕГРЮЛ/ЕГРИП

Официальная интеграция ФНС предоставляет ZIP-архивы XML по FTP с клиентским
сертификатом. Доступны полная база на начало года и ежедневные изменения.
Для собственного поиска по ОКВЭД нужны загрузчик, обработка обновлений и
локальная индексация. Актуальные форматы — ЕГРЮЛ 4.08 и ЕГРИП 4.07; поддержку
старых форматов ФНС продлила до 22.01.2027.
[Техническая модель интеграции](https://www.nalog.gov.ru/rn77/service/egrip2/egrip_vzayim/).

Для юридических и физических лиц годовое абонентское обслуживание стоит
150 000 рублей за один реестр: ЕГРЮЛ и ЕГРИП оплачиваются отдельно. Требуются
оформление доступа и предоставленные ФНС атрибуты доступа.
[Порядок и стоимость предоставления сведений](https://www.nalog.gov.ru/rn77/service/egrip2/access_order/).

### «Прозрачный бизнес» и открытые данные МСП

[«Прозрачный бизнес»](https://pb.nalog.ru/) поддерживает веб-поиск компаний по
ОКВЭД, в том числе нижестоящим кодам, региону и другим критериям. Официальная
документация публичного API такого поиска при проверке не обнаружена.
Наличие запросов веб-интерфейса само по себе не определяет поддерживаемый
контракт интеграции для приложения.

Бесплатный вариант пакетного импорта — [открытый реестр МСП](https://www.nalog.gov.ru/opendata/7707329152-rsmp/).
Он содержит только субъектов малого и среднего предпринимательства.
На дату проверки опубликована XML-выгрузка от 10.09.2026; на странице доступны
ежемесячные выпуски и описание структуры.

Проверенная [XSD реестра МСП](https://file.nalog.ru/opendata/7707329152-rsmp/structure-12052026.xsd)
содержит ИНН и ОГРН, заявительные и отчётные ОКВЭД, основной и дополнительные
коды. Поиск по отрасли возможен после собственного импорта и индексации;
полнота ограничена компаниями и ИП, включёнными в реестр МСП.

### Возможное дальнейшее развитие

1. Для проверки конкретной компании подключить `/egrn/{id}` отдельным сервисом
   с таймаутом, кешированием и терпимой к изменениям схемой ответа. Отдельно
   отображать заявительные и отчётные коды; не смешивать их с семантикой
   основного кода DaData.
2. Если необходим полный список компаний по отрасли, определить требуемое
   покрытие: только МСП либо все юридические лица. Для первого варианта
   спроектировать импорт открытых XML МСП, для второго — интеграцию ЕГРЮЛ
   после оформления соответствующего доступа.
3. До внедрения импорта оценить хранение, обновление и индексацию данных.
   Создание Entity/Unit из найденных записей проектировать отдельным действием
   оператора с проверкой существующих связей.

Платные услуги ФНС не подключались, сертификаты не запрашивались, полные
выгрузки реестров не загружались.
